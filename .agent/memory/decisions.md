# decisions.md — 决策记录（含理由与代价）

> 只记**已经影响代码形状**的决策。每条必须有「代价」，没有代价的决策多半是没想清楚。

## D-2026-10-23-01｜版本口径改由脚本判定，不再靠人眼

- **背景**：`计划书/README.md` 曾写「最新 tag = v1.3.180」而实际 v1.3.181 已发版。手写事实必漂移。
- **决策**：新增 `scripts/check-version-consistency.mjs`，比较 5 处来源；进 CI；发版时加 `--require-tag`。
- **代价**：每次改 VERSION 都要顺带更新 README 声明，多一步手工。

## D-2026-10-23-02｜「VERSION 先于 tag」不算错

- **背景**：门禁第一版把 tag≠VERSION 当硬错误，结果正常发版窗口（bump 后未打 tag）天天红。
- **决策**：默认把「VERSION 领先 tag」记为 note；只有「tag 新于 VERSION」（不可能态）才报错；`--require-tag` 用于发布流水线。
- **代价**：门禁默认宽松，必须靠发版流程记得加 `--require-tag`。

## D-2026-10-23-03｜`db_structure.md` 由脚本从真实库生成

- **背景**：手抄 55 张表必然错；且 `AGENTS.md` 要求三库兼容，手抄无法体现方言差异。
- **决策**：`scripts/gen-db-structure.mjs` 读一次性 AutoMigrate 后的 SQLite 文件生成。
- **代价**：schema 变更后必须重跑生成并提交，否则文档过期；SQLite 不能代表 MySQL/PG 的类型细节（已在文件头声明边界）。

## D-2026-10-23-04｜术语门禁豁免条改词边界

- **背景**：`Unlimited Quota` 因 `limit` 子串被当成限流类豁免，门禁假绿 2 处违规。
- **决策**：`EXEMPT_KEY` 改为 `\b(rate|rates|limit|limits|limited|concurrency|concurrent)\b`。
- **代价**：若将来出现「限额」语义的新 key（如 `credit limit`）仍会被豁免——那是**有意的**，因为限流语境里「配额」才是准确词。

## D-2026-10-23-05｜不代提交他会话的在途改动

- **背景**：工作区内同时存在视觉 V0–V3、i18n 补译、CI/门禁脚本等他人改动。
- **决策**：只提交本会话产出（脚本 + 规格文件 + 文档 + N1 术语修复），不 `git add -A`，不 `git clean`。
- **代价**：本轮提交不构成「完整可发布状态」，发版需等他会话收口或明确接管。

## D-2026-10-23-06｜推送目标固定 `origin`，禁用 `upstream`

- **背景**：`main` 的 upstream 被设为 `QuantumNous/new-api`（非本仓库）。
- **决策**：一切推送显式写 `git push origin main`；禁止 `--force`。
- **代价**：依赖执行者记住这一点（已写入 `known-issues.md` 与本文）。

## D-2026-10-24-01｜CI 门禁必须由 push 触发，否则等于没有

- **背景**：`ci.yml` 仅 `on: pull_request`，而本仓库 37 提交 / 14 tag 全部直接 push main → 6 条门禁 + 三库 job **从未运行**；版本口径门禁红了 ≥2 个版本无人发现。
- **决策**：给 `ci.yml` 加 `push: branches: [main]`，`Test` 步骤改 `bun run test:shards`，frontend timeout 10 → 25 分钟（T-A9）。
- **代价**：每次 push 消耗 Actions 分钟；且加触发后**立刻会红**（必须先修 3 处红项，T-A10 与其同批）。

## D-2026-10-24-02｜不砍项，但用「砍版规则」防估时失真

- **背景**：业主明确"全部都要去做，不管优先级，全部落地闭环"；但上一版 13 个版本的路线只兑现 3 张卡。
- **决策**：路线覆盖 P0–P2 全部 34 张卡（v1.3.196–209）；同时新增砍版规则：某卡经**两次有意义的替代尝试**无进展 → 降级 `Blocked` 并写明缺什么，当版其余卡照常交付，不连环阻塞。
- **代价**：版本号会走得多（14 个），且 Blocked 卡会积累；换来的是不会因为一张卡卡死整条线。

## D-2026-10-24-04｜SSH 改为仅密钥登录（带死手开关）

- **背景**：`passwordauthentication yes` + `pubkeyauthentication no`，root 密码可登；该密码已明文出现在本机记忆与临时 askpass 中。fail2ban 已在压制暴力破解（Total banned 70），但这挡不住"密码一旦泄露"。
- **决策**：生成 `~/.ssh/newapi_prod_ed25519` → 写 `authorized_keys` → **先只开 `PubkeyAuthentication yes` 验证密钥能登** → 再关密码 + `PermitRootLogin prohibit-password` + `MaxAuthTries 3`；全程挂 600s 死手开关（未取消则自动恢复密码登录）。
- **代价**：用户换机/丢私钥就登不上，必须走服务商 VNC 控制台执行 `SOP-主机加固.md` §4.1 的命令。已把私钥路径与应急命令写进 SOP §1。

## D-2026-10-24-05｜ufw 只放行 22/80/443，且用 300s 死手开关

- **背景**：ufw inactive，等于没有主机防火墙；但直接 enable 有小概率把自己锁在外面。
- **决策**：`default deny incoming` + allow 22/80/443 → enable；enable 前挂 300s 自动 `ufw disable` 的后台任务，验证新 SSH 连接成功后再 `touch` 取消。
- **代价**：将来任何新服务（如加监控端口）必须先 `ufw allow`，否则表现是"服务起了但外面连不上"。

## D-2026-10-24-06｜备份加固而不重写，异地副本先做一次性

- **背景**：生产已有 `/opt/new-api/backup.sh`（10-23 落地）且带"非空 + pg_restore -l"校验；真实缺口是**从未演练**、配置未纳入、权限过宽、无异地。
- **决策**：**在原脚本上加固**（保留其余逻辑：`pg_dump -Fc` + 7 天轮转），新增 umask 077 / 目录 700 / 剩余空间守卫 / `.env`+compose+`Caddyfile` 快照；**不换实现**。异地副本本轮用 `scp` 手工拉一份到本机 `~/newapi-prod-backups/` 并核对 sha256。
- **代价**：异地副本会随本机关机而"过期"，**必须尽快定自动化方案**（rsync 第二台 / 对象存储）。
