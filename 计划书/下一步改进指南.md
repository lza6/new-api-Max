## 0. 使用说明（先读）

### 0.1 这份文档怎么用
1. 每个优化项都包含：**现状 → 目标 → 方案 → 落点文件 → 验收标准 → 测试要求**。
2. 严格按「P0 → P1 → P2」顺序执行，每批做完跑通、留证据、提交到 main 再进下一批。
3. 不要一次改多个批次；批次之间有依赖的，先做依赖批次。
4. 完成后在文末「落地台账」登记：批次、提交 SHA、验证命令、证据路径。

### 0.2 项目铁律（来自 AGENTS.md，违反即返工）
- **三库兼容**：任何影响数据库的改动必须 SQLite + MySQL(≥5.7.8) + PostgreSQL(≥9.6) 真实实例验证；迁移/启动至少跑 2 次证明幂等；单测/mock 不算数。
- **JSON 规范**：根模块 JSON 序列化一律走 `common/json.go` 的 `common.Marshal/Unmarshal/...`；relaykit 内走 `relaykit/relayconvert/kitutil`。禁止直接调 `encoding/json`（业务代码）。
- **relaykit 独立**：`cd relaykit && GOWORK=off go build ./...` 必须通过；不得反向依赖根模块。
- **计费安全**：任何用户可控量（图片 n、视频 duration、max_tokens、媒体时长、上游扣费数值）先 bound 再算；quota 转换一律走 `common/quota_math.go` 的 `QuotaFromFloat/QuotaRound/QuotaFromDecimal`（含 `*Checked` 变体并记录 clamp 到日志），禁止裸 `int(float64...)` 转换；不得产生负扣费。
- **认证安全**：认证相关改动先读 OWASP ASVS 与 Cheat Sheet（Authentication / Session Management），服务端强制，审计日志脱敏（禁记密码/验证码/私钥/token）。
- **前端**：先复用 `web/src/components/` 与既有 feature 组件，出现有候选再谈新建；用户文案必须走 i18n `t('...')`；包管理用 Bun；改动后跑 `bun run typecheck` 与 `bun run lint`。
- **Go 规范**：`any` 代替 `interface{}`；`strings.Cut/SplitSeq`、`slices.Contains`、`maps.Copy`、内建 `min/max`、`sync.WaitGroup.Go`；gofmt + 清理未用 import。
- **测试规范**：新增/重写测试用 testify `require`（致命）+ `assert`（非致命）；表驱动、确定性输入、不写假压力/睡眠/随机测试；小改动扩展既有测试文件，不散建测试文件。
- **文档**：不新增 `docs/` 下文件（除非用户明确要求）；规划资产统一放 `计划书/`。

### 0.3 现状快照（真实盘点）

- 前端：React 19 + TS + Rsbuild2 + TanStack Router/Query/Table + Zustand + Base UI + Tailwind4；前端测试文件 **133** 个；i18n 语言 en/zh/zh-TW/fr/ru/ja/vi。

## 2. P0-1 三库 conformance 契约测试套件

### 现状
AGENTS.md 要求所有数据库改动三库验证，但当前是**人肉执行**（启动容器→跑迁移→人工核对），无自动化回归，容易漏。

### 目标
把「迁移幂等 + 三库关键行为」固化为可重复运行的 Go 契约测试，CI 可跑；本地一条命令跑三库。

### 方案
1. 新建 `dbconformance/` 或复用 `test/`（选型：跟随项目现有测试布局，避免新增根级散目录）：
   - 用 `testing` + `github.com/stretchr/testify/require` 表驱动。
   - 每库一组：SQLite（内置）、MySQL、PostgreSQL（DSN 由环境变量注入，缺省 `t.Skip` 并标注 SKIPPED）。
2. 覆盖点（对齐 AGENTS.md 数据库规则）：
   - `AutoMigrate` 全模型：新库跑一次、再跑一次 → 断言第二次无 schema 变更（幂等）。
   - `lockForUpdate(tx)` 行为：MySQL/PG 断言锁生效；SQLite 跳过（语义分支）。
   - 三库保留字列（`group`/`key`）读写、布尔值 `commonTrueVal/FalseVal` 往返。
   - JSON 序列化字段（TEXT 存储）往返；`common.UsingMainDatabase/UsingLogDatabase` 分支。
   - 索引存在性：logs 复合索引、task_events 索引（F2/F3/F4 已修，回归防止回退）。
3. 提供脚本：`scripts/db-conformance.ps1`（或 make target）启动 MySQL/PG 容器（docker compose 一次性）、设 DSN、跑测试、清理容器；输出 PASS/FAIL 明细。

### 落点文件（建议）
- `dbconformance/conformance_test.go`、`dbconformance/helpers_test.go`
- `makefile` 增加 `make db-check`；CI workflow 增加三库 job（可用 `services:` 起 mysql/postgres）。

### 验收标准
- 三库各跑 2 次幂等迁移通过；日志索引断言通过；SKIP 的库在报告中显式标注原因。
- 输出记录：数据库版本 + 命令 + 结果（写入 `计划书/audit-ledger.md`）。
- 严禁以单测/mock 代替真实三库。

### 测试要求
- 每个断言有明确契约描述；新增失败必须真实反映某库行为差异（如 SQLite 不支持 `FOR UPDATE` → 断言分支而非报错）。

## 3. P0-2 计费安全收口（bound + quota_math + clamp 审计）

### 现状
AGENTS.md 已定义计费安全不变量，`common/quota_math.go` 提供饱和转换与 `*Checked` 变体，部分路径已接入（如 openai_image_request_test.go）。但**仍需全量审计**：所有用户可控量是否都在校验层 bound、所有计费路径是否都走 quota_math、clamp 是否都写入日志与 admin_info。

### 目标
- 任何用户可控计费乘数（图片 `n`、视频 `seconds/duration`、分辨率/质量比、batch 数、`max_tokens` 族、媒体时长、上游扣费数值）在进入 quota 计算前**必须 bound**（复用 `dto.MaxImageN`、`relaycommon.MaxTaskDurationSeconds`、`maxTokensLimit`）。
- 所有 quota 转换走 `common.QuotaFromFloat/QuotaRound/QuotaFromDecimal`（含 `*Checked`），记录 clamp 到 `relayInfo.QuotaClamp` → `service/log_info_generate.go` 的 `attachQuotaSaturation`。
- 兜底路径（passthrough `Extra["parameters"]`、task `metadata`、multipart 字段）同样 bound，禁止绕过 DTO 校验。

### 方案（分 4 步）
1. **审计**：`rg` 定位所有 `int(float64(...)*...)`、`math.Round`、`IntPart()`、`*float` 乘数读取点；列出「未 bound / 未走 quota_math / 未记录 clamp」三张清单。
2. **bound 收口**：在每类请求校验器加界（返回 400）；新增 relay 格式从第一天带 bound（valid_request.go 模式）。
3. **转换收口**：把裸转换替换为 quota_math 助手；带 `*Checked` 的路径把 clamp 接入日志标记。
4. **回归**：扩展现有 `common/quota_math_test.go`、`relay/helper/openai_image_request_test.go`、`relay/common/relay_utils_test.go` 风格的表驱动用例；覆盖：饱和不产生负扣费、预扣费失败不静默 wrap、uint 超大值拒绝、NaN/Inf 拒绝。

### 落点文件
- `common/quota_math.go`（如缺助手则补，但优先复用已有）
- `relay/helper/valid_request.go`、各格式 adaptor 的校验器
- `service/log_info_generate.go`（`attachQuotaSaturation` 接入点）
- 相关测试文件（扩展既有，不散建）

### 验收标准
- 审计三清单闭合（每一项给出文件:行与处理结果）。
- 新增边界测试全绿；构造恶意值（如 `18446744073686646784`、`1e30` duration）断言 400/饱和。
- 线上计费行为不变（影子验证：相同请求扣费前后一致）。

## 4. P0-3 认证安全审计（OWASP ASVS 对齐）

### 现状
项目已有 session/JWT/PAT/TOTP/WebAuthn/OAuth 等能力，但未做系统性 OWASP 对齐；安全审计事件需确认脱敏合规。

### 目标
对照最新 OWASP ASVS（Authentication V2 / Session Management V3）逐项核对，修复高危缺口，并给每个修复配回归测试。

### 方案（分模块，先读官方 Cheat Sheet）
1. **会话管理**：登录后 session 轮换；登出全端失效；会话并发上限（已有 `UserSessionActiveLimit` 常量，确认开关生效）；cookie 属性（`Secure/HttpOnly/SameSite`，已有 `security/session-cookie-secure` 经验，确认默认生产开）。
2. **口令**：密码存储（确认走 `common/password_crypto.go` 强度）；忘记密码/验证码：防枚举、防爆破、单次有效、过期。
3. **MFA/TOTP/WebAuthn**：二次验证注册与登录闭环；恢复码单次使用；重认证（改密码/绑定邮箱/敏感操作）。
4. **OAuth/OIDC**：state/nonce、redirect_uri 校验、code 单次、绑定用户确认、降级风险。
5. **API 凭据**：PAT 创建/吊销审计；token 只在创建时明文展示一次；日志脱敏（禁记 key/token/密码）。
6. **审计事件**：`controller/audit.go` 扩展，确认不落敏感字段，记录非敏感上下文。

### 落点文件
- `service/auth_session.go`、`service/auth_token.go`、`middleware/auth.go`、`controller/auth*`、`oauth/`
- `common/password_crypto.go`、`common/totp.go`
- 测试：扩展现有 `auth_session_test.go`、`auth_token_test.go`、`auth_flow_test.go`、`misc_oidc_test.go`

### 验收标准
- 每项给出 ASVS 版本 + 需求 ID + 实现/证据/缺口。
- 失败/过期/重放/绕过场景有回归测试。
- 审计日志抽样确认无敏感字段。

## 7. P1-2 Redis 队列批量落库（日志/任务事件）

### 现状
consume/error 日志已异步 flush（v1.2.34），但仍是直写库的异步化，未真正「批量化落库」；高并发下写放大仍是瓶颈风险。

### 目标
日志/任务事件走 Redis 队列（或内存批缓冲）→ 按量/按时间批量落库，降低峰值写库压力；失败可重试、不丢核心计费数据。

### 方案
1. 设计：`pkg/` 或 `service/` 增加 `batch_flusher`（缓冲上限 + 周期 flush，借鉴 `model/consume_log_flusher.go`）。
2. 计费日志（consume）与普通错误日志分队列：计费走强一致（flush 前落 WAL/重试），错误日志可丢失（尽力而为）。
3. 批量写库复用 GORM 批量 Create；三库兼容（用 `lockForUpdate` 无关路径，避免 SQLite 冲突）。
4. 指标暴露：队列深度、flush 批大小、失败重试次数（`pkg/perf_metrics`）。

### 落点文件
- `model/consume_log_flusher.go`（扩展或新增批缓冲）
- `service/log_traffic.go`、`controller/log.go`
- 测试：`consume_log_flusher_test.go` 扩展

### 验收标准
- 并发写入下，数据库插入速率稳定、队列深度有界、不 OOM。
- 模拟 Redis 故障：计费日志不丢（重试/落盘回退），错误日志可延迟不崩。
- 三库各跑一次批量写入回归。

## 8. P1-3 任务事件流 SSE 断线续传（seq/sinceSeq）

### 现状
`service/task_event.go` + `controller/counting_writer.go` 已有 SSE 雏形（v1.2.27 B4-1 落地），但**断线续传**与前端 live timeline 的健壮性需验证补齐。

### 目标
任务执行过程对用户实时可见：SSE 推送事件，断线后按 `seq`/`sinceSeq` 续传（Last-Event-ID 语义），前端重连不重复不丢。

### 方案
1. 后端：Task 事件旁表单调 `seq`，SSE 端点支持 `sinceSeq` 增量；事件含幂等 id。
2. 前端：`EventSource` 自动重连 + Last-Event-ID 续传；失败回退轮询（兼容不支持 SSE 环境）。
3. 状态机：任务生命周期（排队→执行→成功/失败/超时）事件闭环；清理策略对接 `service/task_event_cleanup.go`（保留期可配）。
4. 权限：仅任务属主/管理员可见事件流。

### 落点文件
- `service/task_event.go`、`model/task_event.go`、`controller/` SSE 端点
- `web/src/features/` 任务 timeline 组件、i18n

### 验收标准
- 断线 30s 重连：事件从断点续传，无重复无缺失（用真实任务验证）。
- 500 条事件压测：前端渲染不卡（虚拟列表/增量渲染）。
- 权限越权访问被拒（回归测试）。

## 12. P2-1 无锁配置快照（atomic.Pointer）

### 现状
渠道/定价/限流配置读路径目前走常规读取+缓存；并发读多写少场景存在锁与一致性开销（曾做内存渠道缓存优化，但快照化未做）。

### 目标
配置读路径无锁快照：`atomic.Pointer[Snapshot]` + 代际戳，写端整体换指针，读端原子读，无需逐字段锁。

### 方案
1. 定义 `Snapshot`：渠道生效配置、定价映射、限流规则、分组映射（序列化后可比较）。
2. 写路径：变更后构建新快照 → `atomic.StorePointer`；读路径：`atomic.LoadPointer` 一次取快照。
3. 热加载：变更事件（渠道更新/定价更新）触发重建；重建成本与频率阈值（防抖动）。
4. 一致性：快照不可变（复制写），避免半更新；失败回退旧快照。
5. 三库/SQLite 兼容：快照构建走只读查询，锁语义不变。

### 落点文件
- `service/channel.go`、`service/` 相关配置读取点、`common/` 快照类型
- 测试：并发读（多 goroutine）+ 交替写，断言读到某代际一致快照

### 验收标准
- 并发基准：读吞吐提升（对比数据）；竞态测试（`-race`）通过。
- 热更新后新请求走新配置、进行中请求不受影响（代际验证）。

## 13. P2-2 通用 webhook/事件子系统

### 现状
项目存在多个支付 webhook（epay 等）与事件型通知（user_notify、webhook.go），格式与幂等策略分散。

### 目标
归一为注册式事件子系统：事件类型注册 → 处理器路由 → 幂等（事件 id 去重）→ 重放（补偿）→ 双向状态机（pending/success/failed/retry）。

### 方案
1. 事件总线 `service/event_bus.go`：`type Event {ID, Type, Payload, CreatedAt}`，注册 `HandleFunc`。
2. 幂等：事件处理记录表（event_id + handler 联合唯一）；失败重试带退避与上限。
3. 支付 webhook 接入：epay 等把验签+解析+事件发布到总线，处理器做账本更新（保持现有对账接口兼容）。
4. 可观测：事件处理耗时/失败/重试指标（perf_metrics）。

### 落点文件
- `service/event_bus.go`（+测试）、`service/epay.go`、`service/webhook.go`
- 新表（event 幂等记录）走 AutoMigrate + 三库验证

### 验收标准
- 同一事件重复投递只生效一次（幂等测试）。
- 处理器 panic/失败自动重试至上限，状态机正确迁移。
- 现支付流程回归（真实 webhook 推送一次、重放一次对比账本一致）。

## 14. P2-3 jsplugin 安全模型升级

### 现状
`pkg/jsplugin`（Sobek）执行任务插件，`plugins/tasks/` 承载；安全检查有 `task_plugin_audit.go`，但沙箱颗粒度、签名、审批链可加强。

### 目标
插件执行最小权限：内容寻址一次性审批（ExecutionGate）+ 分层权限 + 可选的插件写入签名（Ed25519）+ 沙箱降级链（docker→Seatbelt→Bubblewrap→workspace）。

### 方案
1. **ExecutionGate**：插件代码哈希寻址，首次执行前展示代码供审批；审批记录一次性 token，杜绝「审 A 跑 B」。
2. **分层权限**：插件声明所需权限（网络/文件/进程/密钥），执行前校验白名单；无声明默认全禁。
3. **签名**（可选阶段）：Ed25519 签名插件包，管理后台托管公钥；未签名插件默认仅沙箱试运行。
4. **沙箱降级链**：优先 docker 隔离，无 docker 则降级并明示降级日志；禁止静默降级到无防护。

### 落点文件
- `pkg/jsplugin/`、`plugins/tasks/`、`controller/` 任务插件管理、`web/src/features/task-plugins/`

### 验收标准
- 恶意插件（读环境变量/写文件/外联）在沙箱内被拒/被隔离（行为测试）。
- 审批链：改一行代码 → 哈希变化 → 需重新审批（回归测试）。
- 无沙箱环境：明确提示且拒绝高风险请求（fail-closed）。
