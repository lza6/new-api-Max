## 0. 如何使用本指南（先读这里）

1. **按优先级取批**：P0（性能/稳定性/安全）→ P1（体验/可观测性/插件）→ P2（新方向）。同一主题内按「依赖→实现→验证」顺序执行任务卡。
2. **一次只做一批**：禁止「前面改 bug、后面加功能又出新 bug」的穿插；每批独立提交（主题 commit），改完先本地全量验证，再走部署+线上验收。
3. **TDD 是硬要求**：每个原子任务先写失败测试（红）→ 最小实现（绿）→ 重构；验证命令必须真实运行并把输出存入 `计划书/e2e-evidence/`。
4. **禁止假实现**：未跑通不算完成；无法在本机验证的（真实上游、真实浏览器、生产库）明确标「待验证」并给出服务器验证步骤。
5. **保护现有工作**：不 `git reset/clean`、不全量覆盖、不 `-f` 推送；涉及数据库 schema 的改动必须跑 SQLite/MySQL/PostgreSQL 三库矩阵。
6. **文档维护**：本文件夹（`计划书/`）是规划文档的唯一存放处；执行后回填「完成记录」到对应任务卡，并刷新 `graft build`（代码图）。
7. **旧产物清理纪律**：清理只针对「升级后不再被引用的旧产物/残留物/垃圾代码」，必须满足：a) 由当批改动制造且不再被引用；b) 先在 `graft grep` / `rg` 确认零引用；c) 走 git 记录（可回滚），不做物理不可恢复删除；d) 删除前把清单列给用户确认。`node_modules`、`web/dist`、`one-api.db*`、`logs/` 等运行时/构建产物不在本轮清理范围。

## 4. 主题详细任务卡

### T1 热路径性能冲刺（P0 · 目标：单并发网关附加 19ms → 10ms）

**背景与根因（证据）**
- 已落地：异步 consume-log flusher（`model/consume_log_flusher.go`）、请求内复用 `UserSetting`/`UserQuota`、Redis 缓存带宽/流量排行。
- **剩余**：预扣费（pre-consume）与结算仍是同步链路；`scripts/bench-latency.ps1` 在 v1.3.28 上未重跑，10ms 目标状态未知（workflow_status 标 ⏳）。

**方案对比**

| 方案 | 说明 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 只读热路径缓存 | 用户设置/渠道/模型/定价缓存 Redis+内存，TTL 短 | 低风险、可回滚 | 缓存一致性需失效策略 | **推荐先做** |
| B. 预扣费异步化 | pre-consume 进入队列，后置结算 | 附加延迟再降 | 计费正确性风险高、需幂等与对账 | 需 T1-A 后单独授权批 |
| C. 连接池/HTTP 复用收敛 | 上游 transport 复用、dialer 调优 | 稳定收益 | 已部分完成 | 做剩余项 |

**原子任务（TDD）**

1. **基准重测（先立基线）**
   - 命令：`powershell -File scripts/bench-latency.ps1 -DirectUrl <mock> -GatewayUrl <gw> -Bearer <token> -N 60`
   - 产出：`计划书/e2e-evidence/paired-latency-bench-v1.3.28.json`

## 5. QA / TDD 工程标准（横切所有主题）

### 5.1 覆盖率策略（务实地对齐「放弃数量虚荣，守护关键路径」）

- 所有计费/结算、身份/会话、Web 防护、插件沙箱、request-id 链路、迁移幂等路径必须覆盖。
- 新前端功能必须覆盖：点击反馈、加载/空态/错误态、键盘/焦点、touch target、i18n 键集。
- 避免假 fuzz/stress/性能测试（随机输入、大循环、sleep、只 log）和仅覆盖率数字。
- 测试不散放：聚焦的小改动先扩展现有测试文件；每个「特性/修复」最多新增一个必要测试文件。

### 5.2 测试放置规范（AGENTS 摘要）

- 优先在对应 `*_test.go` 或 `src/features/<feature>/__tests__` 中扩展。
- 测试用 `github.com/stretchr/testify/require` + `assert`（Go）；前端按现有 vitest 风格。
- 不把测试写成锁死实现细节的文件布局/私有常量。

## 6. 风险与诚实边界

1. **禁止假实现**：任何「完成」都必须附命令输出/证据文件；本机达不到的（真实上游、真实浏览器、生产库）标「待验证」。
2. **保护用户现有工作**：不 reset/clean、不全量覆盖、不 `-f` 强制推送。
3. **计费正确性**：T1-B 若授权，需幂等、对账、灰度，否则不改结算语义。
4. **三库强约束**：任何 schema/DB 影响必须矩阵验证；不能只靠 SQLite 通过就声称 DB 兼容。
5. **OWASP/ASVS**：身份/会话/密码收到的改动必须读官方 Cheat Sheet + ASVS，按版本引用；未验证不收尾。
6. **Webhook/定时同步**：若用户不确认立项，任务卡保持「待优先级」状态，不在地图上宣称完成。
7. **残留物清理**：只删已确认零引用的旧产物，且保留 git 可回滚路径。

## 附录 C：与 AGENTS.md 硬规则的对接清单（改每一项前必查）

- **计费安全**：必读 `pkg/billingexpr/expr.md`；所有配额换算统一走 `common.QuotaFromFloat/QuotaRound/QuotaFromDecimal`（及 `*Checked` + `attachQuotaSaturation` 审计标记），禁止裸转换；倍率经 `types.PriceData.AddOtherRatio`；不得出现负额/整数溢出——饱和的额度在 pre-consume 必须因额度不足失败，绝不静默回绕。
- **JSON**：根模块一切 marshal/unmarshal 走 `common.*`（不直接 import encoding/json 业务代码）；relaykit 用 `kitutil.*`。
- **relaykit 独立**：不得 import 根模块；改 relaykit 必 `GOWORK=off go build ./...`。
- **数据库三库**：schema 迁移 = 全新库 + 既有库各跑两次；GORM `AutoMigrate`、`lockForUpdate`、raw SQL 方言（commonGroupCol/commonKeyCol）、布尔 default 规避等。
- **身份安全**：任何注册/登录/登出/改密/找回/MFA/WebAuthn/OAuth/会话/JWT/API 凭据改动必须读 OWASP Cheat Sheet/ASVS；审计事件不得记录密码、验证码、恢复码、私钥、可用 token；前端检查不得替代服务端强制。
- **max_tokens/图像 n/任务时长计数**：复用 `dto.MaxImageTokens`、`relaycommon.MaxTaskDurationSeconds`、`maxTokensLimit` 做上限。
- **文档限制**：非用户明确要求不新增 `docs/` 下文件（本计划书在根 `计划书/`，`specs/` 为项目既有资产）。
- **交付合规**：fork 分支/默认 main、`-f` 禁用、按主题 commit、先 fetch 后推、PR 用对应模板；fork 仓库 `-f` 不必要；避免在 PR 中内置机密。
