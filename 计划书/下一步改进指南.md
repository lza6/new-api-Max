## 0.0-B 关键实证结论（改相关代码前必读）

1. **首字慢=上游，非网关**：线上 frt p50≈27s；服务器端成对基准网关附加 ≈0~300ms；上游连 “hi” 都要 1.8~4.4s；请求上下文 25-51 万 token → prefill 20-80s（audit/first-token-latency-prod.md）。
2. **500=RELAY_TIMEOUT 超时**：近 6h 500 类 use_time 全为 300/600s；已修复为 504 + 超时 900s（v1.2.38）。
3. **429/502=上游单渠道超卖透传**：deepseek-v4-flash 仅 1 个活跃渠道（channel 20 yunshuzhilian）；根治=加渠道+健康分路由。
4. **创建 token 不可用=API 不返回 key + 0 额度死胎**：已修复并生产验证（v1.2.37）。
5. **三库迁移**：SQLite/PG15/MySQL8 迁移×2 幂等已验；`deleted_at`/软删、`commonKeyCol` 在测试环境需 `initCol()`（新增 model 测试注意）。

## 9. 三库验证操作手册（每个涉 DB Batch 必跑）

```bash
# 1) SQLite（默认）
go test ./model/... ./service/... -run "Banned|WebRequest|UserProfile|UserSkill|TaskEvent|Webhook" -v

# 2) MySQL 8（docker）
docker run -d --name newapi-mysql -e MYSQL_ROOT_PASSWORD=test -e MYSQL_DATABASE=newapi -p 3306:3306 mysql:8
# SQL_DSN=root:test@tcp(127.0.0.1:3306)/newapi go test ...

# 3) MySQL 5.7 兼容（AGENTS.md 最低版本）：
docker run -d --name newapi-mysql57 -e MYSQL_ROOT_PASSWORD=test -e MYSQL_DATABASE=newapi -p 3307:3306 mysql:5.7

# 4) PostgreSQL（默认 make dev 用）
docker run -d --name newapi-pg -e POSTGRES_PASSWORD=test -e POSTGRES_DB=newapi -p 5432:5432 postgres:15
# SQL_DSN=postgres://postgres:test@127.0.0.1:5432/newapi go test ...

# 5) 启动/迁移至少两次证明幂等；升级路径用最新 Release 建的库跑一遍
```

### 9.5 本地快速启动与 QA 冒烟（项目无 .bat，Makefile 即启动脚本）
```bash
make dev          # PostgreSQL + 后端（开发热重载）
make build        # 前端 build
```
- 已知瓶颈：前端 build 内存峰值 ~4GB（CI 配 NODE_OPTIONS=4096）；SQLite 并发写锁 → 高并发验证用 make dev(PostgreSQL)；每请求写 DB 日志是已知性能债（本版 P1 批量落库方向）；Windows 宿主机 controller 套件 t.TempDir() 清理 audit.db 句柄占用（环境性，Linux CI 不受影响）。

- SQL：连接池默认 1000 → 64（`SQL_MAX_OPEN_CONNS`）；慢查询与 `pg_stat_statements`；日志库切 ClickHouse 或按 `created_at` 分区 + 保留期；`task`/`banned_ips` 索引复核；`pg_dump`/`VACUUM INTO` 定时备份。
- 安全：CSP/HSTS 响应头；会话活跃上限默认关闭（按用户既有要求）；SSRF 双守卫（fetch_setting + url_guard）文档化；默认 root 口令改密流程。

### 18.5 测试与 QA 门（覆盖率 90% 目标）
- 新增/修复一律 TDD：先失败测试 → 最小实现 → 通过 → 重构 → 复验。
- 后端：定向单测 + `-race` + 三库 conformance（复用 B5-1 方案）；前端 vitest + jest-dom + axe 无障碍 + VRT 视觉基线。
- E2E：本地真实实例法已验证可行（见 9.0 证据脚本），生产部署后同法复测留档；禁止把静态检查当 E2E。
- 覆盖率：以仓库现有门槛为准并提高，不降门槛、不加无断言测试。
