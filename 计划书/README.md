## `ops/` —— 运维与工程规范

| 文件 | 是什么 | 什么时候读 |
|---|---|---|
| `SOP-运维手册.md` | 面向「半夜被叫起来处理问题的人」：速查命令、蓝绿部署与回滚、**按症状的排障清单**、事故响应流程、明令禁止的操作 | 任何线上排障 / 部署 / 回滚前 |
| `ADR-架构决策记录.md` | 从代码与注释**逆向提取**的关键架构决策（背景/决策/理由/后果+代价/证据 `file:line`） | 动手改架构相关代码前；想知道「为什么这么写」时 |
| `黄金范例.md` | 本项目**认可的写法**清单（带反向锁的回归测试、有界缓存、安全默认值、前端三态、错误处理不吞错、注释风格）+ 反面清单 | 写新代码前；代码审查时对照 |
| `token-billing-group.md` | 「token计费」分组（按输入上下文阶梯计价）的运维说明：当前阶梯价、**新增/改一个模型必须同时改的 4 处**、强制变更安全流程、排障表、日志字段 | **改任何计费配置前必读**（含 2026-10-09 事故的强制流程） |
| `deploy-zero-downtime.example.sh` | 蓝绿零停机部署脚本的**脱敏模板**（真实脚本含凭据，只在服务器 `/opt/new-api/`） | 想了解部署流程与自动清理策略时 |
| `disk-guard.example.sh` | 每日磁盘守卫脚本的**脱敏模板**：清构建缓存/旧镜像/源码残留，磁盘 ≥85% 只告警 | 排查或预防磁盘增长时 |

> ⚠️ `*.example.sh` 是模板，**不是**可直接运行的脚本；真实版本在服务器上。

## 阅读顺序建议

| 你的目的 | 按顺序读 |
|---|---|
| **接手下一轮改进** | `下一步改进指南.md` → `workflow_status.md`（看进度与未闭环） → `ops/黄金范例.md` |
| **线上出事了** | `ops/SOP-运维手册.md` §4 排障清单 |

| **要写新代码** | `ops/黄金范例.md`（含反面清单） |
