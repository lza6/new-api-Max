## 0. 先更正一个可能的误读：这份审计低估了问题的性质

审计把「6 页互为近重复」「6 页缺 H1」「内部深度 0」「正文平均 13 词」列为**四条独立缺陷**。
实测（`curl` 原始 HTML）表明它们是**同一个根因的四个症状**：

| 实测项 | 结果 |
|---|---|
| 6 个公开页返回的字节数 | **全部 3982，完全相同** |
| `<title>` | 6 页**完全一样**（默认英文标题） |
| `<h1>` 标签数 | **0** |
| `<link rel="canonical">` | **写死 `href="/"`** —— 6 页全都声明"我的正版是首页" |
| JSON-LD | 只有 1 份，且是首页的 `SoftwareApplication`，子页复用 |
| 可跟随的 `<a href>` | **0** |

**根因**：前端是纯 CSR（`web/dist/index.html` 是所有路由共用的一份壳），
路由级 meta 由 JS 运行时写入 —— **不执行 JS 的爬虫看不到任何内容**。

> 所以修复顺序不是"补文案"，而是"让爬虫看得见"。补文案是第 3 步，不是第 1 步。
> 反过来讲：**审计里"内容不够 helpful"的判断，在爬虫能看见内容之前，是无法被证伪的。**

## 1. 关键（Critical）—— 不修则后续所有 SEO 投入都是白费

### C-1 `canonical` 全站写死指向首页　✅ 本轮已修复

| 项 | 内容 |
|---|---|
| **问题** | `web/index.html:24` 是 `href="/"`，且该文件是**所有路由共用的壳**。于是 `/pricing`、`/rankings`、`/about` 等子页全部向搜索引擎声明"正版是首页"，等于是**主动请求不要索引这些子页**。 |
| **证据** | 实测 `curl` 6 个路径，`rel="canonical"` 全部返回 `href="/"`。 |
| **改法** | 服务端按**实际请求路径**注入 canonical（绝对地址）。新增 `controller/spa_seo.go` 的 `BuildSPAIndexHTML`，在 `router/web-router.go:55` 的 SPA fallback 处调用。未命中的路径也 canonical 到自己，**绝不回退到首页**。 |
| **影响文件** | `controller/spa_seo.go`（新）、`router/web-router.go`、`controller/misc.go`（路由表扩展） |
| **验证** | `go test ./controller/ -run TestSPASEO` → `TestSPASEOInjectsPerRouteTitleAndCanonical`、`TestSPASEOUnknownPathKeepsItsOwnCanonical` 通过；线上 `curl -s https://<域名>/pricing \| grep canonical` 应为 `.../pricing` |
| **责任方** | 我（本轮） |
| **工作量** | 小（已完成） |
| **依赖** | 无 |
| **验收标准** | 6 个公开路由各自返回指向自身绝对地址的 canonical；未知路径亦指向自身；单测锁死。 |

### C-2 纯 CSR：爬虫看不到任何路由内容　✅ 本轮已修复

| 项 | 内容 |
|---|---|
| **问题** | 6 页返回同一份 3982 字节空壳。零 `<h1>`、零可跟随链接、零正文。审计的"近重复 / 缺 H1 / 深度 0 / 13 词"全部源自此。 |
| **证据** | 6 个路径原始 HTML 字节数完全相同；`grep -c '<h1'` = 0；`grep -c '<a href'` = 0。 |
| **改法** | 服务端注入：① 路由级 `title` / `description` / `og:*` / `twitter:*`；② 一段**准确**的内容块（`<h1>` + 摘要 + 边界说明 + 站内导航 + 上游官方文档外链），插在 `<body>` 之后、`#root` 之前；③ 一个 `MutationObserver` 脚本在 React 真正渲染出内容后**移除**该块（用户看不到，爬虫看得到）。 |
| **为什么这样做而不是"写更多字"** | 爬虫看不见内容时，写字等于白写。且注入块与页面真实内容一致（仅描述"这页是什么"），**不构成 cloaking**；也刻意不写任何未经证实的数字。 |
| **影响文件** | 同上；内容表在 `controller/misc.go` 的 `seoPublicPaths`（**sitemap / robots / 服务端注入三者的唯一真相源**） |
| **验证** | 单测：`TestSPASEOInjectsCrawlableContentBlock`（H1 存在、内链数 = 公开路由数−1、无自链接、外链带 `rel=noopener`、内容块在 `#root` 之前、移除脚本在场）。线上：6 个路径字节数应**各不相同**、各含 1 个 `<h1>`。 |
| **责任方** | 我（本轮） |
| **工作量** | 中（已完成） |
| **依赖** | 无 |
| **验收标准** | 6 个路径：① 字节数互不相同；② 各含唯一 `<h1>`；③ 各含 ≥5 条可跟随站内链接；④ 内容块在用户侧不可见（React 挂载后被移除）。 |

### C-3 `.art` 顶级域的链接权重与信任成本（**不是缺陷，是约束**）

`.art` 是相对冷门的 TLD，外链生态天然薄。这**不是**可以"优化掉"的东西，但它决定了：
外链建设（见 M-3）比常规域名更重要，且**不要指望短期内靠自然外链**。

**处置**：记录为约束，不产生行动项。不做任何"买外链/换域名"的动作（后者需用户决策，且会连带 sitemap/canonical/证书一起迁移）。

| 项 | 内容 |
|---|---|

| **影响文件** | `controller/misc.go` |
| **验证** | 连续两次抓取 sitemap，`lastmod` 必须**相同** |
| **责任方** | 我 |
| **工作量** | 小 |
| **依赖** | 无 |

## 4. 本轮**明确不做**的事（避免"做错比不做更糟"）

| 不做 | 为什么 |
|---|---|
| 编造作者 / 资历 / 客户案例 / 测试数据 | 审计原文即要求"Do not invent facts"；编造会被判 spam 并直接损害信任 |
| 添加 `FAQPage` / `AggregateRating` / `Review` 结构化数据 | 本站公开页没有对应的真实内容；无中生有是结构化数据的明确违规用法 |
| 堆关键词 / 批量泛化内链 / 购买外链 | 黑帽手段；且当前问题**不是**内容量，是可见性 |
| 为凑词数把注入块写长 | 注入块会在 React 挂载后被移除；它的唯一读者是爬虫，**准确性**远比长度重要 |
| 用 `<noscript>` 装内容 | 执行 JS 的搜索引擎（Google）不会用它；而我们是**真的**在服务端产出内容 |
| 换域名以规避 `.art` 的生态劣势 | 会影响证书 / sitemap / canonical / 用户书签，属重大变更，需你明确决策 |

## 5. 执行顺序与验收清单

```
✅ C-1 canonical 修复（单测 + 线上 curl 双验）

✅ M-1 标题去重（含在 C-1/C-2 的单测里）
─── 上线 ───
⬜ H-3 sitemap lastmod（独立、低风险，建议紧接着做）
⬜ H-2 按路由的结构化数据
⬜ H-1 定价透明度（等你决定价格是否公开渲染）
⬜ M-2 运营者归属（等你提供真实信息）
⬜ M-4 hreflang（先验证路由模型）
⬜ M-5 CWV（需真实浏览器测量）
```

**上线后如何客观验收**（不依赖任何"排名预测"）：
1. `curl -s https://freeapi.tingfengai.art/<path> | grep -E 'canonical|<h1'` —— 6 个路径各自不同；
2. 重新跑一次同款服务器端爬取，对比 `duplicate content`（应从 35 上升到接近满分，因为 6 份字节不再相同）与 `internal links`（应从 50 上升，因为出现真实内链）；
3. **不要**把上述任何一项说成"排名会提升" —— 那是预测，不是诊断。
