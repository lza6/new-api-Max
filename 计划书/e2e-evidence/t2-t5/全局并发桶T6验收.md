# T6 全局真实并发桶（管理员可配置 + 排队）验收报告

> 时间：2026-09-17 · 环境：本地网关 + 服务器慢响应 mock（0.3s/请求）

## 功能
管理员在「系统设置 → 安全 → Global Concurrency Bucket」配置：
- 开关 `relay.global_concurrency_enabled`
- 并发上限 `relay.global_concurrency_limit`（同时处理中的请求数）
- 队列容量 `relay.global_concurrency_queue`（超过则直接 429）
- 排队超时 `relay.global_concurrency_wait_timeout`（排队超时返回 429）

语义：满时新请求**进入有界 FIFO 队列排队**（而非直接拒绝），前一请求完成即放行下一个；队列满/超时才 429。水位（active 当前并发 / waiting 排队数 / limit）经 `/api/status.global_concurrency` 实时暴露，前端设置页「当前负载」卡片展示。

## 真实 E2E 结果

### 排队串行（limit=1，上游 0.3s，并发 4 请求）
```
req1: HTTP 200 (+1539ms)
req2: HTTP 200 (+3004ms)   ← 排队后放行
req3: HTTP 200 (+4223ms)
req4: HTTP 200 (+6100ms)
结论: 4/4 全部 200（串行排队 FIFO，非直接 429）
```

### 并发水位采样（/api/status.global_concurrency）
```
active=1 waiting=4 → active=1 waiting=3 → active=1 waiting=2 → active=1 waiting=0
```
即：始终 1 个在处理，其余逐步从队列消化 —— 正确展示"当前有多少并发 + 多少在排队"。

### 超时拒绝（waitTimeout=3s，limit=1，上游长时间不响应）
```
4 个请求均排队 3 秒后返回 429「网关并发已满，请稍后再试（全局并发上限 1）」
```
