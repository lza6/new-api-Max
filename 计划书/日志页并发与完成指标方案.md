# 日志页「当前并发 + 近1分钟完成」实时指标方案

> 目标：管理端 usage-logs 详情头部实时显示 ①当前每秒并发（in-flight 请求数）②近 1 分钟已完成请求数。
> 数据零额外计算：复用 `middleware.StatsMiddleware()`（engine 根已挂）计数器，不加新请求、不查库。

## 一、现状侦察（实证）

- `router/relay-router.go:17` 在 **engine 根**挂 `middleware.StatsMiddleware()` → 覆盖全站 HTTP（admin+relay）。
- `middleware/stats.go`：`HTTPStats{activeConnections int64}` + `GetStats()`；进入 +1、defer 退出 -1 → **这就是"当前并发"**（每秒瞬时值）。已通过 `GET /api/status/test` 暴露 `http_stats.active_connections`。
- **缺口**：无"近 1 分钟完成数"计数器。
- `controller/log.go GetLogsStat`（admin-only `/api/log/stat`）返回 `{quota, rpm, tpm}`；`rpm` 是最近 60s 消费日志计数（依赖 DB+异步 flush，有滞后），不是"完成的 HTTP 请求数"。
- 前端 `web/src/features/usage-logs/components/common-logs-stats.tsx`：已有 `StatBadge`/`TrafficBadges`（admin-only），加两个 badge 即可。
- **i18n 审计发现**：上一轮 traffic 三个键被加到了 locale 文件的 **root 命名空间**（非 `translation`）。实测 `t('Traffic today')` 在 zhCN 返回英文原文 → 该批文案**实际未翻译**。本次新键放 `translation` 内并补全翻译，同时将 traffic 3 键迁入 `translation` 修复。

## 二、方案

### 后端
1. `middleware/stats.go`：
   - 新增 `completedWindow`：61 格按秒分桶滑动窗口（`marks[sec%61]=sec` + `counts`），互斥锁保护；
     请求结束 defer 里 `completed.add(time.Now())`。
   - `StatsInfo` 增加 `completed_last_minute`；`GetStats()` 返回两者。
2. `controller/log.go GetLogsStat`：`data` 增加
   `concurrent_requests`（= active_connections）、`completed_last_minute`。
   `GetLogsSelfStat`（用户侧）不加（并发是全站指标，仅 admin）。

### 前端
3. `types.ts LogStatistics` + `constants.ts DEFAULT_LOG_STATS` 增加两个可选字段。
4. `common-logs-stats.tsx`：admin-only 增加 `StatBadge("Concurrent now", concurrent_requests)` 与
   `StatBadge("Completed last minute", completed_last_minute)`；admin 查询加 `refetchInterval: 5000` 实时刷新。
5. i18n：7 语言 locale 的 `translation` 内新增 2 键 + 迁移 traffic 3 键并翻译；`bun run i18n:sync` 归一化。

### 测试
6. `middleware/stats_test.go`：滑动窗口（同秒累加/跨 61s 桶复用/旧桶淘汰/1 分钟窗口求和）+ 中间件并发增减（gin httptest + goroutine 阻塞）。
7. `common-logs-stats.test.tsx`（vitest）：admin 渲染两个新 badge；用户视图不渲染。
8. 本地 E2E：mock 上游(3999) + 本地 SQLite + 5 路并发 relay → 飞行中 `concurrent_requests>=5`，完成后 `completed_last_minute>=5`，保存 JSON 证据。
