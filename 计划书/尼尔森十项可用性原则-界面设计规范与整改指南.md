## 0. 先读这一段：本文档的边界与用途

### 0.1 本文档解决什么问题

本项目已积累大量 UI 组件与工程规范（`web/AGENTS.md` 3.3/3.9/3.12/3.14），但**没有把「可用性」翻译成可判定条款的文档**。后果是本轮实测到的这些现象可以长期共存而无人判违规：

- `quota` 在 136 个文案键里被译成 额度 79 / 配额 42 / 容量 1 / 其它 14
- 同一「启用」状态：`Active → 生效`、`Enabled → 已启用`
- 状态徽章两套实现并存（`StatusBadge` 87 个文件用纯文字药丸，`ui/badge` 48 个文件用底色药丸）
- 错误提示文案写着「please rotate it on the channels page」，但**没有任何可点按钮**
- 后端 261 处 `ApiErrorMsg`，其中 **39 处直接把 Go 原始错误 `err.Error()` 抛给前端**
- 空状态的 `emptyAction` 通道已经从组件层铺到页面层（`data-table-page.tsx:122,453,568`），但 **feature 层 0 次使用**

本文档做三件事：**① 把 10 条原则落成 42 条可判定条款（§2）；② 给出跨页面统一交互契约（§3）；③ 给出 16 张原子任务卡 + 验收命令 + 回滚（§5/§7/§8）。**

## 1. 设计目标 → 验收口径

| 目标 | 判定口径（可验收） | 对应原则 |

| G1 降低认知成本 | 新用户不看文档，3 分钟内完成「建 Key → 调一次模型」；页面不出现无释义的内部术语 | H2 H6 H10 |

## 3. 全局交互契约（跨页面硬约束）

> 这一节是规范核心：**新页面必须按此实现，老页面逐步对齐**。落地后回写 `web/AGENTS.md`（N16/N12）。

### 3.1 四态矩阵（每个数据区必须显式实现四态）

| 态 | 触发 | 必须渲染 | 现成实现 |
|---|---|---|---|
| Loading | `isLoading && !data` | 骨架屏（列表）或 `LoadingState`（局部） | `DataTablePage`（`data-table-page.tsx:86-101`）已统一收口 |
| Refreshing | `isFetching && data` | 置灰/不撤行 + **"更新于 Ns 前"** | `DataTablePage` 有置灰；时间戳缺失 |
| Empty | `data.length === 0` | 图标 + 「为什么空」+ **一个下一步动作按钮** | `EmptyState`（`action`）与 `DataTablePage.emptyAction`（**feature 层 0 使用**） |
| Error | `isError` | 人话标题 + 原因 + 「重试」 | `ErrorState`（`onRetry`） |

**反例（禁止）**：空数据只渲染 `No data`（当前 14 处）。

### 3.2 提交契约（所有写操作）

1. 提交中：按钮 `disabled` + 文案进行时 + **spinner** + 表单区 `inert`。
2. 成功：`toast.success` + 关闭/重置 + `invalidateQueries`。
3. 失败：字段级走 `form.setError`；非字段走 `handleServerError`（不得另写一套文案）。
4. 重复提交：请求未返回前不得再次触发。
5. 失败后**不得清空**已填内容。

## 7. 验收矩阵

### 7.1 自动化（能跑就必须跑）

| 层次 | 命令 | 适用 |
|---|---|---|
| 类型 | `cd web && bun run typecheck` | 全部改 TS 的任务 |
| Lint | `cd web && bun run lint` | 全部 |
| i18n | `cd web && bun run i18n:check` | N1、N10、N16、任何碰 locale 的任务 |
| 定向单测 | `cd web && bunx vitest run <受影响文件>` | 全部（**不跑全量**） |
| 后端定向 | `go test ./controller/... ./common/...` | N15 |
| 术语门禁 | `node web/scripts/check-术语一致性.cjs`（N1 产出） | N1 及后续改 locale 的批次 |
| 构建 | `cd web && bun run build` | 仅收尾/合并前 |
| 浏览器 E2E | `node web/e2e-local/<脚本>.cjs`（320/390/1440） | N5、N6、N7、N8、N9、N11、N13 |

### 7.2 人工走查清单（每批次 15 分钟）

1. `/keys` 新建 Key：必填留空 → 字段下报错且首错获焦；提交中按钮禁用 + spinner；成功后列表刷新。
2. `/channels` 编辑 → 改字段 → 点关闭：**必须**弹「未保存，是否离开」。
3. 批量删渠道：走统一确认弹窗，显示影响数量，危险按钮为实心危险色。
4. 触发额度不足/429/500：首行人话 + 有可点动作 + 可复制 request id。
5. 新账号 `/usage-logs` 空数据：有空状态 + 下一步按钮；可多选。
6. `Ctrl/⌘+K`：可唤起，能键盘选中并跳转；界面上有快捷键提示。
7. 320px 视口：无横向滚动、无叠印。
8. 切英文再切回：无裸 key、无中文残留（术语统一后）。

### 7.3 证据留存

截图/JSON 放 `计划书/e2e-evidence/<批次>-usability/`；每张任务卡完成后在 §5 表格追加「结果 + 日期 + 命令输出摘要」，**未跑过不得写 PASS**。
