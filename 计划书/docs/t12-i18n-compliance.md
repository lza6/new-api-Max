# 专项分析 · 国际化（i18n）与合规深挖（T12 纵深）

> 定位：主指南 §T12 的**深挖文档**：i18n 机制、术语一致、合规提示路径；只读整理。
> 生成：2026-09-25 · 锚点：`web/src/i18n/`、`i18n/`（后端）、`web/AGENTS.md`。

## 1. 机制（证据）
- 前端：i18next + react-i18next + browser-language detector；语言 en（base）/zh/zh-TW/fr/ru/ja/vi；扁平 JSON `web/src/i18n/locales/{lang}.json`，key 为英文源串；组件用 `useTranslation()` + `t('English key')`。
- CLI：`bun run i18n:sync`（web/）。
- 后端：`nicksnyder/go-i18n/v2`，en/zh。

## 2. 缺口（主指南 §T12）
- 术语表（技术/计费/订阅/渠道）未沉淀；7 语言一致性与未翻译 key 扫描未固化；合规提示（隐私/条款/订阅退订）视产品形态补。

## 3. 落地路径（建议）
1. **术语表**：在 `计划书/docs/` 或 web 文档新增 `translation-glossary`（中英对照核心词：quota/额度、channel/渠道、subscription/订阅、refund/退款、task/任务、plugin/插件……）；术语优先于直译。
2. **一致性扫描**：脚本/命令 `bun run i18n:sync` 后核对各语言 key 完整性；CI 可选加 check。
3. **合规提示**：订阅条款/退订/自动续费提示按产品决策补充（需用户确认文案），不擅自加法律结论；合规范围不扩大（不做法务判断）。

## 4. 纪律
- 所有用户可见文案走 i18n（英文 key）；不硬编码中文/多语言。
- 新增 key 后 `bun run i18n:sync` 回填 7 语言（缺译标 TODO/待译，不伪造译文）。
- 术语一致优先；不改既有已发布文案语义除非产品决策。

## 5. 验证
- `cd web && bun run i18n:sync && bun run typecheck && bunx vitest run src/i18n`（若有测试）
- 扫描脚本输出未译 key 清单（真实文件证据）。

## 6. AI 生成内容标识（2026-09-27 补充，仅文档化）

> 适用场景：网关聚合的 AI 文本/图像/视频生成类渠道。以下为「建议核对项」，不构成法律意见，
> 具体标识义务以部署所在地法规与平台规则为准（如《人工智能生成合成内容标识办法》等）。

- [ ] 站点/服务条款：声明对外提供 AI 生成内容，标注内容由第三方模型生成，非人工创作。
- [ ] 图像/视频任务产物：建议在产物元数据或下载侧提供「AI 生成」标识位（前端可展示 badge）。
- [ ] 日志/审计：任务日志已含 model_name 与上游 usage；如需溯源「是否 AI 生成」已有足够字段，无需新增。
- [ ] 未成年人/深度合成高风险类别：若上架深度合成类任务（换脸/拟声），须按平台规则前置核验，本网关不主动放开。
- [ ] i18n：若展示「AI 生成」标识，文案走 i18n 键（如 `ai_generated_badge`），7 语言补齐。

> 结论：本网关作为 API 网关，主要职责是流量转发与计费；生成内容标识属「下游应用/前端展示」层，
> 网关侧提供能力（任务日志含 model/usage 溯源）即可，不擅自改变产物。
