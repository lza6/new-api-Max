## Required Changes（P1，建议下一版本修复）
1. **热路径重复订阅查询**（controller/relay.go 矩阵校验 + middleware/subscription-rate-limit.go）
   - 问题：`CheckSubscriptionModelAccess` 与 `resolveSubscriptionTier` 各自对每个 relay
     请求调用 `GetAllActiveUserSubscriptions`（主库索引读）。未订阅用户（常见情形）
     也会各产生一次 DB 读 → 每请求 2 次订阅查询，违背网关"热路径少 DB"原则。
   - 建议：二者合并为单次解析（请求上下文缓存），或对"无订阅"结果做 10~30s 负缓存
     （购买/到期时失效）。属性能优化，非正确性缺陷。

## Suggestions（P2）
2. **多 active 订阅档位语义**：`resolveSubscriptionTier` 取 `end_time desc, id desc`
   的第一条；同一用户多订阅并存时仅最新到期者生效。建议在套餐/订阅文档注明该语义。
3. **模型矩阵分隔符**：`modelsToJson` 按 逗号/中文逗号/换行 拆分；模型名含逗号会误拆。
   当前模型名不含逗号，v1 可接受，建议注释说明限制。
4. **进程内限流**：订阅 RPM/并发为进程内计数（与 T5/T6 一致）；多实例部署需接 Redis，
   已在代码注释与 HTML 报告注明，非本次缺陷。
