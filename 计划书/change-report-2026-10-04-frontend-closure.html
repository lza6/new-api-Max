1. 上下文（为什么要改）

new-api-Max 是一个已生产部署的 AI API 网关（Go 后端 + React SPA）。一次终局审计把我带到了三个层面的真实缺口：

① 新手转化漏斗断点

新用户注册后：建了 Key 却看不到明文、无法一键去对话；Playground 默认模型硬编码 gpt-4o（本站根本不在售）；模型广场没有"去对话"入口。

② 无障碍（a11y）断链

SkipToMain 跳过导航链接指向 #content，但全站没有该目标 → 键盘用户按 Tab+Enter 页面纹丝不动（比没有更糟）。登录页甚至完全没有跳过链接。

③ 列表页静默失败

共享表格组件 DataTableView 只有"加载/空"两态：查询失败时渲染成"暂无数据"，10+ 个列表页（密钥/用户/渠道/兑换码…）失败被当成空列表，用户无法感知也无法重试。

2. 直觉（怎么想的）

"能用的产品"而非"有按钮的页面"

  • 闭环优先：建 Key 的价值不是"创建成功"的 toast，而是用户拿到那串只显示一次的密钥并马上能试用它。所以创建成功后不关抽屉，改停在结果步。
  • 复用而非新建：a11y 修复复用项目已有的 SkipToMain 与 <main> 语义元素；错误态复用项目已有的 ErrorState 组件（含 Retry 按钮），不手写。
  • 在正确的层级改一次：列表错误态不逐页 hack，而是在组合组件 DataTablePage 加一层 isError 透传 —— 改一处，所有表受益。
  • 动态优先于硬编码：默认模型交给已有的 getModelFallback 在模型列表加载后自动选第一个在售模型。
  • 证据说话：每个"修好了"都配真实浏览器 E2E 或单元测试，不靠"看起来对"。
