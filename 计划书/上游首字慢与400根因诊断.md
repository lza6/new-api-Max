# 上游首字慢 / status_code=400 根因诊断报告（实证）

日期：2026-09-19（v1.2.30 线上）
状态：诊断完成（实证），配置优化已落地（RELAY_TIMEOUT）

## 1. 用户反馈的 3 个问题
1. 「上游正常响应却被判 400」：日志 status_code=400, inference request is invalid，计费路径=上游返回。
2. 「上游首字 3s、站内 10s」：首字延迟被放大。
3. 「站内高负载时首字被拉大，上游没问题」。

## 2. 实证方法（真实 E2E，非推断）
对同一上游（稳定渠道 #20 = yunshuzhilian.asia，OpenAI 兼容）发同一流式请求（deepseek-v4-flash, max_tokens=16, "hi"），
计时到首个 data 行（首字），分别在 **服务器本机直连上游** vs **走网关** 两组交错测量。

### 2.1 首轮（低峰）
直连：21.8s / 9.0s / 5.2s（平均 12s，波动极大）
网关： 3.8s / 13.8s（平均 8.8s）
→ 网关甚至更快，说明网关未系统性放大；上游本身慢且波动（5-22s）。

### 2.2 交错同窗（direct/gw 交替，各 5 轮）
d: 4024/2297/1950/4098/2278（中位数 ~2278）
g: 3715/3876/2582/6045/4083（中位数 ~3876）
→ **网关中位数放大 ≈1.6s（1.7 倍）**；绝对首字 2-6s；流传输（首包→done）秒级内，放大主要发生在首包之前
（鉴权/渠道选择/计费/连接/上游首包 = 请求进网关到上游首包之间）。

## 3. 根因结论（诚实，基于数据）
- **上游 vendor（yunshuzhilian.asia）是首字慢的主因**：直连实测 2-22s 且波动剧烈；高峰 frt（网关日志 FirstResponseTime-StartTime）30-156s 与上游自身慢+重试一致。
- **网关有中等首字放大 ≈1.5-2s（中位数 1.7 倍）**，来自 2 核小机高并发下的站内热路径（鉴权/渠道选择/计费/连接/CPU 调度）；放大集中在首包之前，流传输透传正常。
- **400 = 上游真实拒绝**：网关透传正确性已验证（正常请求经网关返回 200 完整 SSE，模型/参数原样透传）。"inference request is invalid" 是上游对特定请求内容返回的错误消息，网关原样透传（非本站判定）。

## 4. 已排除的技术嫌疑（代码证据）
- 首包缓冲 fallover：`relay.stream_fallover` 默认 off，未安装 FirstPacketBufferWriter（buffered_writer.go）→ 非元凶。
- 流式 scanner 每行 LogDebug：`logger.LogDebug` 受 `common.DebugEnabled` 门控（logger.go:92），线上 Debug 关闭 → 零 Sprintf/I-O → 非元凶。
- HTTP 连接池：RelayMaxIdleConns=500 / PerHost=100（init.go:115-116）→ 充足。
- 流式写客户端 Flush：透传 SSE 首包正常到达（首包≈上游时间）→ 正常。
- 响应头 CopyCodexSSEHeaders / SetEventStreamHeaders：O(1)，非瓶颈。

## 5. 落地优化（保守，遵「严禁重构」）
- **RELAY_TIMEOUT=0（无超时）隐患**：慢请求（上游 20-156s）无超时长期占用连接/资源 → 高负载放大加剧。
  **已落地**：服务器 docker-compose 为 new-api 增加 `RELAY_TIMEOUT=300`（宽松有限超时，防无限挂起占资源），并重启验证。
- **建议（文档，不擅自改动）**：
  1. 为唯一不稳定渠道（#20）增加**备用上游渠道**；届时可评估开启 `relay.stream_fallover`（首包超时默认 15s 需按上游实际首字调大，避免慢但正常的上游被误判为空流切换）。
  2. 监控上游 yunshuzhilian.asia 健康分（B3-3 已提供）与 frt 分布（consume log 已记录），确认是否为 vendor 超卖。
  3. 若首字 SLA 苛刻，考虑升级实例（2 核→4 核）降低 CPU 竞争；或选择首字更稳的供应商。

## 6. 验收证据
- 交错 5 轮数据（见 §2.2）已留档
- 正常请求经网关 200 SSE 透传成功（§3）
- RELAY_TIMEOUT 配置落地并重启验证（§5）
