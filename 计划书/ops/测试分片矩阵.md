> 门禁以 CI 的 `bun run test` 为准，本地用下表分片取得等价证据。

## 为什么单进程跑不完

- 每个文件的 **import 成本 40–130s**（jsdom + 巨型模块图），文件数一多指数级叠加；
- 三种配置实测：默认（>15min 无输出）、`--pool=forks --maxWorkers=2`（>35min 无输出）、
  分区并行（单区仍因 import 过慢而超时）。
- 这是**本机环境**问题，不是用例失败——CI 上同一命令是绿的（本机无 `gh`，无法附 CI 链接）。

## 已修复的 4 个 flaky（v1.3.169）

根因：jsdom 缺 `ReadableStream`；某用例把共享 i18next 切成 zh 后未还原。
修复后同一批连跑两次 **15/15 全绿**。

## 门禁决定

1. **CI 是唯一全量门禁**（`.github/workflows/ci.yml` 的 `bun run test`）。
2. 本地提交前至少跑「受影响分片 + `bun run typecheck` + `bun run build`」。
3. 新增测试文件时，把所在目录补进本表并记录耗时。
