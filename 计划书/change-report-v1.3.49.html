commit 3dc97f27e + 83c8038fa · main · 2026-09-28

1. 上下文（Context）

中继渠道适配器（ollama×5、ali、kilwa）此前每个外呼都新建 &http.Client{}——虽然这些 client 共享 Go 的 http.DefaultTransport，但其 MaxIdleConnsPerHost=2：高并发访问同一上游时 keep-alive 复用不足，导致连接反复建-拆（延迟 + 端口占用）。连接池挂在 Transport 上，http.Client 只是配置壳（每次持有自己的 Timeout）。

§4.1.1 独立审查同步返回 CONDITIONAL PASS（无 P0/P1；P2×3 补测试/注释），本批一并收尾。

2. 直觉（Why）——设计取舍

  • 共享 Transport 单例：所有渠道客户端指向同一个调优 Transport（PerHost=32/Total=100），连接池天然共享（构造性证明）；各 client 保留原有 Timeout（30min/1h/120s/不限时），行为不变。
  • 非 SSRF 路径专用：仅渠道/网关配置受控 URL 用共享池；用户可控 URL 继续走 SSRF 客户端（安全边界不变）。
  • 不新增环境变量：调优为常量默认值，无需运维配置；回滚=改回裸 client（行为等价，仅退化连接池）。
