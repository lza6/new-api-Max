## 1. 问题陈述

本站是生产环境运行的 AI API 网关（`freeapi.tingfengai.art`，4 核 4G / 80G 盘 / 75Mbps）。
运营方希望**在用户明确授权的前提下**，采集对话数据用于模型训练数据集的构建，
并把数据冷存到云盘（本站用 OneDrive），而不是占用网关本地磁盘。

当前**完全没有**这套能力：既没有声明/授权流程，也没有采集链路，也没有云盘对接。
同时发现两个相关缺陷：
- **日志文件无上限增长**（实测 24 个文件 / 单个最大 173MB / 合计 870MB，只增不减）；
- **README 过时且含上游项目残留**，非全面中文。

## 2. 用户故事（按优先级）

### Story 1 — 用户授权采集（P1，必须先做）

**作为** 本站注册用户
**我想要** 在「个人资料」里看到「参与模型训练数据采集」开关，打开前必须阅读并同意免责声明
**以便于** 我在充分知情的前提下自愿参与，并可随时撤回。

**验收标准**
- [ ] 开关位置：个人资料页，与既有设置同区（复用既有设置项渲染范式）
- [ ] 开关下方**常驻小字**说明「采集什么、做什么用、存哪里」
- [ ] 首次打开弹**免责声明**（含：采集范围 / 用途 / 存储位置 / 撤回方式 / 不采集敏感信息），
      必须显式点击「同意」才真正开启；点「取消」则开关回弹为关闭
- [ ] 状态**实时更新**（成功/失败都有反馈，不是静默）
- [ ] 撤回后立即停止后续采集（已采集的数据保留策略见 Story 6）
- [ ] **授权状态可查询**：用户能看到自己当前是已授权 / 未授权

### Story 2 — 增量采集去重（P1，核心算法）

**作为** 运营方
**我想要** 只采集**新增**的对话内容，不重复上传同一段对话
**以便于** 云盘不被重复数据填满，上传带宽不被浪费。

**验收标准**
- [ ] 能识别「同一会话的新增轮次」：长期会话中历史部分 token 高度重复，只上传**增量**
- [ ] 能识别「同一轮次的内容未变」：内容哈希未变则不上传
- [ ] 去重判据**可解释**：记录为何判定为增量（供排障与审计）
- [ ] 边界：会话被编辑 / 重生成 / 删除时，判据仍成立（不重复、不丢新内容）

### Story 3 — 异步采集，零请求延迟影响（P1，硬约束）

**作为** 调用方
**我想要** 采集对我的请求延迟**没有可感知影响**
**以便于** 网关的核心价值（低延迟中转）不被采集功能破坏。

**验收标准**
- [ ] 采集**不在请求热路径上同步执行**（请求返回与采集彻底解耦）
- [ ] 队列有界（内存不随流量无限增长）；满载时**丢弃采集而不是阻塞请求**
- [ ] 自适应：根据当前带宽 / 队列水位 / 云盘可用性动态调整采集节奏
- [ ] 压测证明：开启采集前后，请求 p95 延迟无可感知劣化

### Story 4 — 云盘目录结构与冷存储（P1）

**作为** 运营方
**我想要** 数据在云盘里按 `日期 / 用户名 / 模型名` 三级目录自动归档
**以便于** 我可以按天、按用户、按模型定位数据。

**验收标准**
- [ ] 一级目录 = 日期（如 `2026-10-14`），二级 = 用户名，三级 = 模型名
- [ ] 目录**按需自动创建**，已存在则复用（不报错、不重复创建）
- [ ] 文件**不会无限增大**：单文件达到阈值即**分片轮转**（新分片命名可区分且可排序）
- [ ] 上传失败可重试；重试不产生重复文件
- [ ] 凭据来自**配置**（环境变量 / 管理端），不硬编码进仓库

### Story 5 — 管理员视图（P1）

**作为** 管理员
**我想要** 看到采集总量与云盘状态
**以便于** 判断是否需要干预（扩容 / 暂停 / 排查）。

**验收标准**
- [ ] 管理员后台有**总开关**（默认开；但**前提是云盘凭据已配置**，未配置则不可开启并明示原因）
- [ ] 显示：今日采集的**用户数 / 对话数 / 体积**，云盘**已用 / 可用 / 差额**
- [ ] 显示：云盘当前**文件夹数 / 文件数**、当前日期
- [ ] 可按日期查看「哪天采集了多少」
- [ ] **总开关关闭时**，用户个人资料页**不出现**采集开关（而非显示一个点了无效的开关）

### Story 6 — 免责声明与合规（P1）

**作为** 运营方
**我想要** 采集行为有明确的声明与用户同意留痕
**以便于** 合规且可自证。

**验收标准**
- [ ] 免责声明文案完整（采集范围 / 用途 / 存储 / 撤回 / 不采集项）
- [ ] 用户同意**留痕**：记录同意时间与声明版本（版本变更后需重新同意）
- [ ] 撤回可自助完成
- [ ] 声明文案走 i18n，全语言无漂移

### Story 7 — 日志分片轮转（P2，独立缺陷）

**作为** 运维
**我想要** 日志文件有大小与数量上限、并按大小分片
**以便于** 磁盘不被日志写满（当前实测 870MB 且只增不减）。

**验收标准**
- [ ] 单文件达到阈值即分片；分片文件名可排序、可区分
- [ ] 保留窗口有上限（数量 + 总字节双上限）
- [ ] **绝不删除非本程序产生的文件**（同目录可能有其它数据）
- [ ] 当前正在写入的文件永不被删

### Story 8 — README 重写（P2）

**作为** 新人 / 部署者
**我想要** README 全面、准确、纯中文（保留必要英文术语）
**以便于** 我能按文档把项目跑起来。

**验收标准**
- [ ] 全中文（技术术语/路径/命令保留英文）
- [ ] 与实际代码一致（启动、配置、部署、验证命令真实可用）
- [ ] 无上游项目残留的过时内容
- [ ] **保留项目保护标识**（new-api / QuantumNous 归属信息不得删改）

### Story 9 — 多云盘对接可扩展（P3，架构预留）

**作为** 运营方
**我想要** 将来能接入其它云盘（OSS / S3 / WebDAV）
**以便于** 不被单一供应商锁定。

**验收标准**
- [ ] 存储后端抽象出接口，OneDrive 是其中一个实现
- [ ] 新增后端不需要改动采集核心逻辑
- [ ] 未实现的后端**明确报错**，不静默失败

## 3. 非功能性需求

| 维度 | 要求 |
|---|---|
| **性能** | 热路径零同步采集开销；采集走异步队列且有界；请求 p95 无可感知劣化 |
| **可用性** | 云盘不可达时**不影响网关正常服务**（采集降级，请求照常） |
| **内存** | 采集队列与缓冲有硬上限；不得因采集导致 OOM（容器限 900MB） |
| **带宽** | 自适应：识别本站上行带宽与云盘吞吐，避免打满导致用户请求变慢 |
| **并发** | 高并发下唯一性/去重正确；目录创建竞态安全（并发建同名目录不报错） |
| **安全** | 凭据不落仓库；不采集密钥/令牌/验证码等秘密；授权状态服务端强制 |
| **合规** | 用户显式同意 + 可撤回 + 同意留痕（时间 + 声明版本） |
| **可观测** | 采集成功率/队列深度/上传字节/失败原因可查 |
| **兼容** | 三库（SQLite / MySQL / PostgreSQL）schema 一致、迁移幂等 |
| **可维护** | 存储后端可替换；配置项有默认值与缺失时的清晰报错 |

## 4. 成功指标

- 用户可在 ≤3 步内完成授权（进个人资料 → 开开关 → 同意声明）
- 开启采集后，网关请求延迟与开启前相比无可感知差异（压测证据）
- 云盘目录结构与规格一致（人工核对截图/列举证据）
- 日志目录在长期运行后**稳定在上限内**，不再单调增长
- 管理员视图数字与云盘实际内容一致（可交叉核对）

---

## 5. 明确不做（Out of Scope）

- ❌ **站内图床 / 本站存储用户图片**（用户明确要求：用云盘，不占本站）
- ❌ **未授权用户的数据采集**（无同意绝不采集）
- ❌ 采集**非对话类**数据（如计费明细、密钥、支付信息）
- ❌ 训练模型本身（本功能只做数据采集与归档）
- ⏸ 除 OneDrive 外的其它云盘**实现**（只做接口预留，Story 9 为 P3）

---

## 6. 关键约束（来自项目宪法）

1. **生产优先**：必须真实链路验证，禁止以静态审查/mock 冒充完成（宪法 I）
2. **计费安全**：采集不得触碰计费路径（宪法 II）
3. **安全基线**：凭据管理、服务端强制授权（宪法 III）
4. **三库兼容**：新表三库成立且迁移幂等（宪法 IV）
5. **性能**：网关不得给用户请求增加可感知延迟（宪法 V）——**本功能的最大风险点**
6. **i18n**：新增文案全语言同步（宪法 VI）
7. **保守改动**：不做无关重构（宪法 VII）

## 7. 已知风险

| 风险 | 影响 | 缓解方向 |
|---|---|---|
| 采集拖慢请求 | 核心价值受损（宪法 V） | 异步 + 有界队列 + 满载丢弃 + 压测证明 |
| 上行带宽被上传打满 | 用户请求变慢 | 自适应限速（识别带宽峰值） |
| 长期会话增量算法误判 | 重复上传浪费 / 丢新增 | 可解释判据 + 边界用例 |
| 凭据泄漏 | 云盘被滥用 | 只从环境变量/管理端读取，不入仓库 |
| 去重状态膨胀 | 内存/DB 增长 | 有界状态 + 过期清理 |
| 云盘故障 | 采集失败堆积 | 降级不影响请求 + 有界重试 + 明确告警 |

## 8. 待澄清（Clarify 阶段）

## Clarifications

### Q1: 采集的数据具体是什么内容？只存对话文本，还是含请求/响应全文？

**Context**: 决定存储体积、隐私边界与去重算法。
**Answer（依据用户原话「采集的对话数据」+「不能影响用户请求」）**：
只采集**对话语义内容**——即消息的 role + 文本内容（含 assistant 回复），
**不采集**请求元数据中的敏感项（API Key、token、IP、用户密码类字段）。
请求中的图片等大对象**不入训练集**（用户明确「不需要站内图床」，
且图片走云盘另论，本 spec 范围只做对话文本）。

### Q2: 云盘凭据从哪来？管理员配还是环境变量？

**Context**: 决定是否需要一个配置界面 + 凭据如何保护。
**Answer**: 两者都要，**以环境变量为部署级来源**（`ONEDRIVE_*`），
管理端只做**状态显示与连通性测试**（不落地明文密钥到 DB，避免与「密钥不落库」的
既有安全基线冲突）。未配置时管理端总开关**不可开启**并明示原因。

### Q3: 「用户新会话」如何判定？增量上传的粒度是什么？

**Context**: 这是用户特别点名的算法难点——「长期会话很多 token 都一样」。
**Answer**: 以**会话**为去重单元、以**消息轮次**为增量单元：
- 会话级：`conversationId` 标识同一会话
- 轮次级：每条消息算内容指纹（role + 规范化文本 + 顺序位）
- 上传时只取「上次上传水位（watermark）之后」的新增轮次
- 内容未变（指纹相同）不重传；水位持久化，进程重启后仍有效
- 边界：编辑/重生成会产生新指纹 → 视为新增（不丢内容）；删除不回滚已上传（不重复传）

### Q4: 采集是「实时」还是「周期批量」？

**Context**: 用户说「打开这个按钮就开始实时采集」，但也说「不能影响延迟」。
**Answer**: 对用户**表现为实时**（开启后新对话即进入采集），
实现上是**异步管道**：请求结束 → 投递到有界内存队列 → 后台 worker 批量上传。
两者不矛盾：「实时」指用户感知（无需手动触发），不等于「在请求路径里同步做」。

### Q5: 单文件多大分片？文件命名如何保证可排序且不冲突？

**Context**: 用户要求「怎样才不会导致一个文件无限增大，轮转」。
**Answer**: 单文件达到阈值（如 8MB，可配）即切分片；
命名 `part-0001.jsonl` 递增且**零填充**（保证字典序 = 时间序），
并带时间戳与随机后缀防并发冲突。分片号单调递增，重启后从云盘列举恢复。

### Q6: 同目录下可能有其它文件，清理逻辑的边界？

**Context**: 宪法 VII「保守改动」+ 误删不可逆。
**Answer**: 只处理**匹配本程序命名规则**的文件（前缀 + 后缀双重校验），
目录/其它文件一律不碰；当前写入文件纳入保护名单。
已在日志轮转（Story 7）的 13 个用例中锁定该边界。

### Q7: 多租户下用户的「用户名」能作为目录名吗？非法字符怎么办？

**Context**: 用户名可能含 `/`、`..`、emoji、超长等，直接拼路径会**路径穿越**或失败。
**Answer**: 目录名做**白名单化 + 长度截断 + 冲突消歧（附用户 ID）**：
只保留字母数字与 `-_.`，其余替换为 `_`；空结果用 `user-<id>`；
截断到安全长度；同名不同用户用 ID 后缀区分。**绝不直接使用原始用户名**。

### Q8: 去重水位状态存哪？会不会无限增长？

**Context**: 宪法 V 禁热路径 DB 同步写；但水位需要持久化。
**Answer**: 存**独立表**（按会话 id 唯一键），只在采集 worker 里读写
（**不在请求热路径**），并对已完成/过期会话做清理，保证有界。

### Q9: 管理员总开关关闭时，已授权用户的数据怎么处理？

**Context**: 用户明确要求「管理员关闭了，用户那边就不应该有开关」。
**Answer**: 总开关关闭 = **立即停止全部采集**（worker 停止消费），
用户个人资料页**隐藏**该开关；已采集数据**保留**（撤回 ≠ 删除，
删除策略由运营方另行决定）。总开关重新开启后恢复。

### Q10: 回收（撤回）后，已上传的数据要删除吗？

**Context**: 合规要求用户可撤回；但删除云盘历史数据是不可逆操作。
**Answer**: 本 spec **不实现自动删除**（不可逆操作需用户/运营方明确决策）。
撤回 = **停止后续采集**并在 UI 明确说明「停止采集」与「删除已采集数据」是两件事，
后者需联系管理员。**不诚实地暗示「撤回即消失」是合规风险**，故文案必须准确。
